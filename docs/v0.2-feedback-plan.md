## 1. 语音：为什么不能用

Redmi K80 / HyperOS 大概率没有 Google 的语音识别服务，`SpeechRecognizer.isRecognitionAvailable()` 返回 false，所以 App 只能手输。**不是权限问题**。

三个选项：

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A. 键盘语音（今天可用） | 在输入框里用搜狗/Gboard 的语音键 | 0 开发、立即可用 | 不是连续转写 |
| B. 云端实时 ASR（推荐） | 阿里云/腾讯云流式 ASR，App 送 PCM，服务端转发 | 中文准确、可连续 | 需要账号/key，按量计费 |
| C. 自建 Whisper | 服务器跑 faster-whisper | 隐私、无第三方 | GPU/CPU 成本，延迟 1–3s |

建议 B。需要你提供：**阿里云还是腾讯云 + ASR 的 key**。没有 key 就先做 A，并在 App 里明确提示"用键盘语音"。

## 2. 关于"只是 RAG"

当前不是 RAG：卡是**会前编译**出来的 `qa` 页面（L1/L2/L3 + 引用），现场只做本地匹配。你看到的"总结感"来自编译质量，不是检索。

你要的"重召回后再 LLM 回答"应该加在**兜底层**，而不是替代预编译卡：

```text
问题
 ├─ 本地卡命中（0.1–0.8s）→ 直接出 L1/L2/L3
 ├─ 命中弱/没有 → BM25 召回 source blocks + claim/metric
 │                 → LLM 基于召回内容回答（1.5–3s）
 │                 → 标注 degraded + 引用
 └─ 召回也空 → 兜底话术
```

- 新增 `POST /v1/ask`：输入问题 + pack，返回组装卡 + 引用。
- App 在本地未命中时调用；不阻塞 L1（L1 先显示"没准备"）。
- 每条回答必须能落回 block；落不回就丢弃。
- 如果要求"每次都 RAG"，L1 0.8s 就保不住，需要把目标改成 2–4s——这个要你确认。

## 4. Web 后台与双端互通

当前认证是 **device_id 即用户**：手机和电脑登录会变成两个用户，数据不互通。必须先改账号模型：

- **邀请码 = 工作区（workspace）**；同一邀请码的手机和 Web 看到同一份数据。
- 设备表：一个 workspace 多个 device token。
- 迁移：你现有的 `test` 用户和两份材料映射到 `W1-DEMO` 工作区。

Web 控制台（运营台，不是 Wiki UI）：

- 文档：列表、批量上传、删除。
- 任务：排队/运行/失败、重试。
- 审核：页面/卡片列表、看依据、批准/拒绝。
- 卡包：已发布 pack、卡片预览、复制分享。
- 发布：APK 版本管理（见下）。
- 鉴权：`ADMIN_TOKEN` 或 workspace 管理员 token；局域网先这样。

## 5. APK 下发升级

- 后端新增 `releases` 表：`versionCode / versionName / notes / sha256 / path / active`。
- Web 后台：上传 APK、填版本号、发布/下架。
- App 启动/设置页：`GET /v1/app/latest`，比较 versionCode。
- 有更新 → 提示 → 浏览器下载 APK → 系统安装。
- **Android 不允许静默安装**（除非设备管理员/企业 MDM），所以是"提示 + 下载 + 用户确认"；这是平台限制，不是没做。
