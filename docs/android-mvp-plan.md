# Android MVP 交付计划

> 日期：2026-10-25 · 当前进度：后端 D1–D5 已完成（上传/解析/DeepSeek 编译/异步 job/审核发布），Android 尚未开始。
> **更新 2026-10-26**：JDK 17 + Android SDK 35 + Gradle 8.9 已装好，Demo APK 已构建（`android/dist/promptwiki-demo-0.1.0.apk`），待真机安装验证。
> 目标：给你一台真机能装的 APK，而不是只有源码。

## 1. 结论（按今天开工算）

| 交付 | 时间 | 范围 |
|---|---|---|
| **可安装 Demo APK** | **11 月 3–6 日**（7–10 个工作日） | 单文档 → 卡包 → 现场提词；系统 ASR + 手输兜底；离线；屏幕触发 |
| **3–5 人内测 MVP** | **11 月 12–18 日**（13–18 个工作日） | 多文档/场景、蓝牙键、审核编辑、复盘、反馈、弱网与异常处理 |

前提：

1. 本周内确定构建方式（本机 Android Studio / GitHub Actions 二选一）。
2. 后端补 2 个 App 必需接口：`GET /packs/{id}`、`GET /packs`（当前只有 review/approve）。
3. 有一台 Android 8+ 真机（最好再有一副蓝牙耳机）可测试。

如果工具链从零装，整体顺延 1–2 天。

## 2. 为什么不是这两三天

- 这台机器只有 **Java 8**，没有 Android SDK / adb / Gradle；我可以写工程，但**不能在本机编译 APK**。
- 后端还缺“App 拉取已批准卡包”的读接口；现在只有审核/批准。
- 中文 ASR、蓝牙按键、后台保活必须真机调，模拟器测不出来。
- 当前卡是“按文档”生成，不是“按一场对话选 20 张”；Demo 先用单文档，内测前再补场景 prep。

## 3. 范围

### Demo（11/3–6）

- 邀请码登录 + 设备 token。
- 从手机选 1 份 PDF/Word/TXT 上传。
- 发起编译 job，轮询进度（约 1–2 分钟）。
- 卡包预览：12–15 张卡，一键全部批准。
- 现场页：大按钮触发，L1 → L2 → L3 渐进，引用弹层。
- 红卡兜底优先；黄卡标记。
- 已批准卡包本地缓存，飞行模式可用。
- 系统 `SpeechRecognizer` 转写 + 手动输入兜底（国内无 GMS 机型可能不可用）。

### 内测 MVP（11/12–18）

在 Demo 上加：

- 3–5 份文档 → 场景卡包（选 20 张、排序、必答标记）。
- 蓝牙耳机媒体键触发（兼容性矩阵，屏幕按钮始终可用）。
- 卡片级审核：改一句、排除、批准（写 Pin）。
- 会后复盘：触发/采纳/兜底统计，未答好问题加入下一版。
- 弱网、断网、后台被杀、ASR 断开的恢复。
- 基础设置：后端地址、清缓存、删除数据。

### 明确不做

自动问题检测、TTS、锁屏可用、眼镜、iOS、多人协作、Pin/冲突的完整 UI、支付。

## 5. 构建方式（需要你选）

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A. 本机 Android Studio** | 在这台机器装 Android Studio + SDK 35 + JDK 17 | 出包快、能真机调试 | 下载约 2–4GB，首次 1–2 小时 |
| **B. GitHub Actions（推荐）** | 我写工程 + workflow，push 后自动出 debug APK | 不依赖本机 SDK、可重复构建 | 需要你给一个 GitHub 仓库；首次配置半天 |
| **C. 只给源码** | 我写完整工程，你自己构建 | 最快拿到代码 | 不是 APK，你需要 Android Studio |

## 6. 验收标准

- Android 8+ 真机安装成功，冷启动 ≤3s。
- 上传 1 份文档 → 12 张以上可用卡，≤3 分钟（含 LLM）。
- 触发到 L1 p95 ≤800ms（本地命中）；L2 ≤1.5s；L3 ≤3s。
- 断网后已批准卡包仍可触发、看引用。
- 引用可点开原文/页码；无出处不展示。
- 连续 3 场会话无崩溃；红卡必须兜底在前。
- 蓝牙键在 2/3 副耳机上可用；不可用时屏幕按钮正常。

## 7. 主要风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 国内机型没有 Google ASR | 无法语音转写 | 手输兜底；内测前接云端流式 ASR |
| 蓝牙按键映射不统一 | 触发失败 | 屏幕大按钮 + 兼容性矩阵 |
| 后端只在局域网 | 手机连不上 | Demo 同 Wi-Fi + 电脑 IP；内测前部署公网 |
| 单文档卡包不够 | 场景覆盖低 | 内测前做场景 prep，合并多文档 |
| 审核只有一键批准 | 质量不可控 | Demo 接受；内测前加卡片级编辑 |
| 后台保活/锁屏限制 | 现场中断 | 前台服务 + 常亮；P0 不承诺锁屏 |

## 8. 需要你定的事

1. 构建方式选 **A / B / C**（建议 B）。
2. 手机型号 + Android 版本；是否有蓝牙耳机。
3. Demo 后端用**局域网**（同一 Wi-Fi）还是已有公网服务器。
4. 是否接受“系统 ASR + 手输兜底”作为 Demo 的语音方案。
