# 提词卡 PRD v0.1（L3：Wiki 隐形）

> 状态：Freeze Candidate · 日期：2026-10-25 · 对应技术契约：[Wiki Schema v1.0](wiki-schema-contract-v1.0.md)
> 一句话：**会前 10 分钟编译，会中 1 秒开口，会后 5 分钟复盘；用户只看到卡，不看到 Wiki。**

---

## 0. L3 的定义（先定死）

| 用户可见 | 用户不可见 |
|---|---|
| 卡包、卡（L1/L2/L3）、依据、来源页、复盘、反馈 | Wiki、页面、图谱、索引、frontmatter、冲突记录、Pin、编译 |
| "这张卡来自 3 份材料" | 页面如何 CREATE/UPDATE/LINK |
| "这句话有冲突，先照兜底说" | 冲突如何检测、如何裁决 |
| "改这一句，下次别再改回去" | 这句话被写成了哪个字段的 Pin |

**L3 不是"没有 Wiki"，而是"Wiki 只做后端"。** 内部仍按 v1.0 契约存 Markdown + YAML；产品层只暴露"卡"和"依据"。

**三条产品红线：**

1. 不出现"知识库/Wiki/整理资料"这类需要用户维护的概念。
2. 任何情况下，用户最多两步就能看到"下一句说什么"。
3. 红卡必须比绿卡更早给出兜底，不允许"看起来自信"。

---

## 1. 问题与洞察

**用户不是没有知识，是在被问住的那 3 秒里取不出来。**

现有两类产品都差最后一步：

- 通用 AI / Copilot：答得顺，但不像我、没依据、现场不敢用。
- 个人知识库 / LLM Wiki：建得漂亮，但会前不会打开、会中来不及查。

**洞察**：高 stakes 对话的准备，本质是**把知识预编译成"可开口的句子"**，而不是建一个更全的库。所以产品单位不是"页面"，是"卡"。

**假设（待验证）**：用户愿意在会前花 10 分钟过 20 张卡，但不愿意花 10 小时整理知识库。

## 2. 用户与场景

### 2.1 目标用户

| 优先级 | 人群 | 场景 | 为什么痛 |
|---|---|---|---|
| P0 | 技术/产品岗面试者 | 面试 | 项目细节多、数字多、怕说错 |
| P0 | 早期创始人 | 路演/投资人会 | 同样的问题被问 50 遍，每次说法不一致 |
| P1 | B2B 销售/客户成功 | 客户会 | 产品细节、案例、报价边界容易说错 |
| P1 | 晋升答辩/媒体访谈 | 答辩/采访 | 时间短、追问尖锐、不能临场编 |

### 2.2 首发内测（W8）

- **对外**：2 位路演/答辩用户 + 1 位销售用户（允许带资料、无伦理争议）。
- **对内 dogfood**：2 位面试用户（团队自己/朋友），验证极端场景。
- 明确不做"替考/代答"营销；产品里不出现 stealth、隐形、作弊相关词。

### 2.3 JTBD

> 当我即将面对一个会被追问的高 stakes 对话时，我想在 10 分钟内确认"最可能被问的 20 个问题，我各有一句能开口、有出处的话"，这样我在现场不会卡住，也不会说错。

## 3. 成功时刻（按时间顺序）

1. **上传 5 份材料，5 分钟内看到 20 张卡**，其中至少 16 张我敢用。
2. **会前 10 分钟**：改 2 张、钉 1 句、确认 2 张红卡怎么兜底。
3. **现场按下按钮，0.8 秒看到 3 个关键词**，1.5 秒看到骨架。
4. **被追问时点开 E1**，能看到原话、哪份材料、第几页。
5. **会后 5 分钟**：标完有用/没用，系统把 3 个没答好的问题放进下一版。

## 4. 四个界面（只有四个）

### 4.1 今日（首页）

```text
┌─────────────────────────────┐
│ 下一场：云栖科技 · 11-03 14:00 │
│ 卡包 20 张 · 2 张需确认 · 已预载 │
│ [ 会前 10 分钟 ]  [ 直接进入现场 ] │
├─────────────────────────────┤
│ 待复盘：昨天 · 3 个问题没答好      │
│ [ 5 分钟复盘 ]                   │
└─────────────────────────────┘
```

- 只做三件事：进会前、进现场、进复盘。
- 没有"知识库"入口，没有"我的页面"。

### 4.2 卡包（会前）

```text
第 3/20 张                     ●●●○○
为什么选择我们公司？            黄 · 2 个来源
[支付账务出身] [高并发一致性] [实时链路]
1. 支付账务出身，做的是高并发一致性
2. 账务 12 个服务，日均 2.3 亿笔
3. 云栖在补实时链路，团队 12 人
[ 改一句 ] [ 钉住 ] [ 这题没用 ] [ 看依据 ]
```

- 上下滑卡，不进入"页面"。
- "改一句"直接编辑 L2 某条；保存即生成 Pin，下次重编译不被改回。
- "这题没用"进入排除列表，下一版不再生成。
- 红卡强制显示"兜底怎么说"与原因，必须点"我知道了"才能开始。

### 4.3 现场（核心）

```text
┌─────────────────────────────┐
│ 14:12  ·  已听 18 分钟   ● 录音中 │
│                             │
│  2025 对账 P1               │
│  补偿任务漏退款              │
│  我牵头复盘                  │
│  补了检查清单                │
│                             │
│  ▸ 展开骨架（1.5s）           │
│                             │
│  [     点按提词（耳机键同）     ] │
│  耳机键也可触发               │
└─────────────────────────────┘
```

- 触发：屏幕大按钮 + 蓝牙耳机媒体键；按下有震动 + 100ms 内视觉反馈。
- L1 先出，L2 随后；L3 折叠，点开才出。
- 红卡：兜底文案置顶，L2 需再点一次展开。
- 每个数字/断言有 `E1` 角标，点开是底部弹层（原话 + 材料名 + 页码），不是 Wiki。
- 未命中：显示"没准备" + 兜底 + 2 条最相关原话；不现场编。
- 录屏/截屏不特殊处理；不承诺"对方看不见"。

### 4.4 复盘

```text
这场 42 分钟 · 触发 11 次 · 采纳 7 次 · 兜底 2 次
─────────────────────────────
14:12 为什么选择我们   有用
14:20 最大失败          用了兜底
14:31 迁移怎么做        有用
...
没答好的 3 个问题 → [ 加入下一版 ]
```

- 只做三件事：看时间线、标反馈、把没答好的问题加入下一版。
- 转写默认不长期保存；用户可开"保存本次记录"。

### 4.5 内部审核台（不发布给用户）

- Web 页面，给算法/运营用；卡片级 diff、依据、Pin 影响、冲突提示。
- 用户 App 里只保留单卡编辑；批量审核在控制台完成。
- 控制台不叫"Wiki 编辑器"，叫"卡包审核"。

## 5. 核心流程与时延预算

### 5.1 首次上手（≤8 分钟）

1. 手机号/邀请码登录（30s）。
2. 选场景模板：面试 / 路演 / 客户会（10s）。
3. 上传 3–5 份材料：简历、项目文档、JD/BP（2 min）。
4. 等待编译：显示"正在生成 20 张卡"，可离开，推送通知（3–5 min）。
5. 试看 5 张样卡 → 确认 → 进入卡包（2 min）。

### 5.2 会前 10 分钟

1. 过 20 张卡（6 min）：滑、读、标"没用"。
2. 改 2 张（2 min）：只改 L2 里那句不顺的。
3. 处理红卡（2 min）：确认兜底，或补一份材料重建。
4. 点"开始"→ 预载卡包 + 检查离线可用。

### 5.3 现场一次触发

```text
按下（0ms）→ 视觉反馈（≤100ms）→ 读当前转写缓冲（≤20ms）
→ 本地匹配 20 张卡（≤10ms）→ L1 渲染（≤50ms）
→ L2（+50ms）→ L3 点开（≤300ms，含引用）
```

- **时延从"按下"算，不从"对方说完"算。** 这是手动触发的最大好处。
- ASR 缓冲滞后 >1.5s 时，显示"还在听"+ 最近 5 个问题快选，不让用户干等。

### 5.4 会后 5 分钟

1. 看时间线（2 min）。
2. 标 5–10 个反馈（2 min）。
3. 把 1–3 个没答好的问题加入下一版（1 min）→ 后台生成草稿，次日确认。

## 6. P0 功能与验收

| # | 功能 | 验收标准 |
|---|---|---|
| F1 | 导入 PDF/Word/TXT/MD | 20MB 内；解析出 block + 页码；失败有可读原因 |
| F2 | 场景与卡包 | 一场对话一个卡包；支持面试/路演/客户会模板 |
| F3 | 生成 20 张卡 | 5 份材料 p50 ≤5 min；≥16 张人工判定"能用" |
| F4 | 卡片审核/编辑/Pin | 编辑保存 ≤1s；重编译后该句不变（ledger 可查） |
| F5 | 红卡门禁 | 红卡未确认兜底，不允许点"开始" |
| F6 | 现场触发 | 屏幕按钮 + 蓝牙媒体键；触发到 L1 p95 ≤0.8s |
| F7 | 三层展示 | L2 p95 ≤1.5s；L3 p95 ≤3s；L3 折叠 |
| F8 | 引用 | 每个数字/断言可点开原话+材料+页码；解析失败则不展示并降级 |
| F9 | 置信度与兜底 | 红卡兜底置顶；黄卡标记；绿卡正常 |
| F10 | 离线 | 已预载卡包可完全离线触发；引用可看；反馈排队 |
| F11 | 会话与复盘 | 时间线、触发/采纳/兜底统计、未答好问题加入下一版 |
| F12 | 隐私 | 一键删除材料与卡包；转写默认不长期保存；录音指示常驻 |
| F13 | 反馈 | 有用/没用/用了兜底/需修改；离线排队同步 |

**P0 不含**：自动问题检测、下一题预取、TTS、多人协作、Web 端、iOS、眼镜、Wiki 浏览/图谱/页面编辑。

## 7. 指标

### 7.1 北极星

**现场有效提词率** = 被标记"有用"或"改后采用"的卡次数 / 触发次数。目标 ≥50%。

### 7.2 过程指标

| 指标 | 目标 | 说明 |
|---|---|---|
| 首包生成时长 p50 | ≤5 min | 5 份材料、20 张卡 |
| 首包可用率 | ≥80% | 人工判定"能用"的卡 / 20 |
| 会前完成率 | ≥80% | 打开卡包并点"开始"的比例 |
| 会前耗时 p50 | ≤12 min | 从打开卡包到开始 |
| 目录命中率 | ≥85% | 触发后命中已有卡 |
| BM25 兜底后命中率 | ≥95% | 含降级 |
| L1 p95 | ≤0.8s | 按下到首屏 |
| L2 p95 | ≤1.5s | |
| L3 p95 | ≤3s | |
| 引用可追溯 | 100% | 抽检 50 张卡 |
| 幻觉抽检 | ≤5% | 50 条陈述人工标注 |
| 采纳率 | ≥50% | 内测 |
| 两周留存 | ≥60% | 内测用户愿意继续用 |

### 7.3 反指标（出现即视为失败）

- 红卡未提示兜底就展示 L2。
- 触发后 >2s 无任何反馈。
- 用户为了找一句话，翻了 3 层以上。
- 用户说"我还得先整理知识库"。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 首包质量差（鸡汤/重复/无依据） | 第一次就流失 | 5 份文档门槛、模板、人工审核、红黄绿、样卡确认 |
| 现场没命中 | 用户不再信 | 预载 + 本地匹配 + 兜底 + 快选；命中率看板 |
| ASR 延迟/断网 | 按了没反应 | 手动触发 + 缓冲匹配 + 离线卡包 + 明确状态 |
| 安卓后台被杀/锁屏限制 | 现场中断 | 前台服务 + 常亮 + 通知；不做锁屏承诺（P0） |
| 蓝牙按键不兼容 | 触发失败 | 屏幕大按钮兜底；W6 做机型/耳机矩阵 |
| 伦理/平台风险 | 下架/口碑 | 对外首发路演/答辩/销售；不出现 stealth 词；用户知情 |
| 隐私（简历/聊天） | 信任崩塌 | 最小化采集、默认不留转写、可删除、密钥不落端 |
| 8 周做不完 | 延期 | 砍 P1；审核台先 Web；iOS/眼镜不做 |

| W4 | 卡包发布/版本/预载 + Android 壳（登录/卡包/现场静态） | 手机能下载并离线打开卡包 |
| W5 | 本地匹配 + 触发 + L1/L2/L3 + 引用弹层 | p95 达标（真机、4G） |
| W6 | 流式 ASR + 蓝牙触发 + 会话记录 | 真实对话中 10 次触发 ≥8 次命中 |

**明确砍线**：自动检测、TTS、多人、iOS、眼镜、Wiki UI、复杂权限、支付。

## 10. 已冻结的默认决策（不同意请在 W1 推翻）

1. **L1 按 0.8s p95 做**（验收表口径），不按 1.5s。
2. **Pin 只做 `field` 锚点**，`section` 放 P1。
3. **绿色 = 2 独立来源 + 人审 + 无冲突 + 未过期**，不放松。
4. **预测问题在"会前准备"时生成**，不在导入时生成。
5. **P0 手动触发**，自动检测 P1。
6. **不发布 Wiki 浏览/编辑入口**，审核台内部用。
7. **Android 先做**，iOS 不做。

## 11. 待验证的假设（W1–W2 用 5 份真实文档验证）

- 用户是否真的愿意为一场对话上传 3–5 份材料？
- 20 张卡是否覆盖真实提问的 85%？
- 用户改的是"措辞"还是"事实"？（决定 Pin 粒度）
- 红卡兜底会不会让用户觉得"这不就是没准备"？
- 5 分钟生成是否能被接受，还是必须 <2 分钟？

## 12. 发布门槛（W8）

- 3 个外部用户 × 3 场真实会话；无 P0 事故。
- L1/L2/L3 p95 达标；引用 100%；幻觉抽检 ≤5%。
- 采纳率 ≥50%；愿意继续用 ≥60%。
- 数据删除可用；转写默认不落盘。
- 对外文案通过"非作弊"审查：不出现 stealth/隐形/代答。
