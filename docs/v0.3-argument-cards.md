# v0.3 论证卡：从"摘要"到"可自圆其说"

> 触发：2026-10-26 反馈——"1–4 条只是摘要；点数字要能跳进论点、技术和架构说明；每个答案要有置信率；AI 要能基于资料自圆其说。"
>
> 落地：v0.3.1（2026-10-26）· 后端 `points` + 规则置信度 · Android 点 1–4 弹层 · Web 后台可展开 · `pack-20261025-06` 已重编译

## 1. 设计原则

"自圆其说"不是让模型自由发挥，而是：

1. **每条摘要可展开**：结论 → 机制/架构/流程 → 证据 → 取舍/边界。
2. **每个数字有出处**：展开内容里的数字也必须能在原文 quote 里找到；找不到就不写。
3. **资料不足就说边界**：不允许用行业常识补全；展开里明确"资料没写"。
4. **置信度是规则估算**：按独立证据块数量给分，不伪装成统计概率。
5. **展开不替代摘要**：L1/L2 仍是 1 秒能扫完的现场层；详情按需点开。

## 2. 卡片结构

```json
{
  "question": "……",
  "l1": ["关键词"],
  "l2": ["摘要 1", "摘要 2", "摘要 3"],
  "points": [
    {
      "index": 1,
      "summary": "与 L2 第一条同义",
      "detail": "结论 → 机制/架构/流程 → 证据 → 取舍/边界，80–180 字",
      "followups": [
        {"question": "如果被追问……", "answer": "不超过 80 字"}
      ],
      "confidence": {"level": "yellow", "score": 60, "reasons": ["single_evidence"]},
      "citations": [
        {"source": "source:doc-xxx", "block": "b-0002", "quote": "逐字原文", "page_label": "……"}
      ]
    }
  ],
  "fallback": "兜底话术",
  "confidence": {"level": "yellow", "score": 60, "reasons": ["single_evidence"]},
  "citations": []
}
```

- `l2` 与 `points` 一一对应；App 点第 N 条打开 `points[N-1]`。
- 旧 pack 没有 `points`：App 用 L2 行合成，详情只有摘要；重新编译才有完整展开。
- 页面 frontmatter 仍按 schema v1.0，不把 `points` 写进 `card`（避免破坏 schema）；`points` 只进 pack 和 QA 正文的"逐条展开"。

## 3. 置信度规则

`rule_v1` 简化版：

| 独立证据块 | level | score | 现场表现 |
|---|---|---|---|
| ≥2 | green | 85 | 可直接说 |
| 1 | yellow | 60 | 可说，但要标"按资料" |
| 0 | red | 30 | 先兜底，不展开 |

- 只按**独立 block 数**，不把同一句话的多次引用算多条。
- UI 显示"置信度 60% · 依据 1 条"；设置/帮助里注明"规则估算，不是统计概率"。
- 追问答案里的数字也必须过 quote 校验；不过就丢掉该追问。

## 4. 交互

```text
提问 → 本地命中 → 卡片
  L1 关键词
  L2 摘要 1  [展开 ›]
  L2 摘要 2  [展开 ›]
  L2 摘要 3  [展开 ›]
  [查看依据] [展开全文]

点"展开 ›" → 底部弹层
  论点 2 · 置信度 60%
  摘要
  展开说明（含技术/架构/取舍）
  可能被追问 Q/A
  依据 quote + 页码
```

- 红卡仍先展示 fallback；点"展开骨架"后才显示 L2 与可展开点。
- L3 是整张卡的完整文本，仍然保留；详情是"按论点下钻"。

## 5. 编译 prompt 约束

- 每个 L2 对应一个 point，summary 同序同义。
- detail 80–180 字，必须包含"机制/架构/流程"中的至少一个，否则就是复述。
- followups 2–3 个，问题像面试官，回答不超过 80 字。
- 数字必须能在该 point 的 evidence_refs 的 quote 中找到。
- 资料不足时，detail 写"资料没写到的边界"，不要补行业常识。
- 只允许引用给定 claim/metric 页面。

## 6. 验证

- 后端测试：points 数量与 L2 一致；score ∈ {30,60,85}；detail/summary 非空。
- 真实编译：12 张卡、每张 3 个 points、detail ~150 字、2 个追问、逐点引用 2 条。
- Android：点 1–4 弹出详情；旧 pack 不崩溃。
- Web 后台：卡包详情可展开 points。

## 7. 没做的

- story/entity 页面与叙事线。
- 跨文档冲突检测、Lint 门禁。
- 逐点人工编辑/Pin。
- 置信度的统计校准（目前是规则分，不是概率）。
