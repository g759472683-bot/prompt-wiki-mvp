# v0.4：跨文档自洽、论点 Pin、置信度校准

> 2026-10-26 · 对应三条反馈：跨文档冲突、逐条论点人工修改/Pin、置信度统计校准。
> 原则：规则先跑通、数据可追溯、没有样本就不假装"统计校准"。

## 1. 跨文档自洽检查

### 规则

扫描 `wiki/pages/` 下的 active `metric` / `claim` 页面：

1. **metric_value**：同一 `metric.key`（没有 key 则用标题归一化）在多份文档中值不同 → 高危。
2. **claim_statement**：同一 claim 标题在多份文档中表述不同：
   - 数字不同 → 高危；
   - 仅措辞不同 → 中危。

- 只比较**不同文档**；同一文档的重复页不算冲突。
- 每条冲突带：主题、级别、说明、各文档的值/quote。
- 只提示，不自动改卡；人工决定用哪个口径。

### 接口 / UI

- `GET /v1/consistency` / `POST /v1/consistency/scan`
- 报告写到 `wiki/consistency.json`
- Web 后台 → “一致性”：显示高危/中危、材料与值
- App 首页：拉取摘要，显示“X 个高危 / Y 个中危”

### 当前边界

- 规则扫描，不是语义定理证明；标题不同但语义相同的 claim 可能漏报。
- 还没有“采纳某个口径 → 自动改所有卡”的联动。
- 后续可加 LLM 语义对比，但要标“模型判断”，不能当确定事实。

## 2. 逐条论点 Pin

### 数据

`point_pins` 表：`user_id + qa_id + point_index` 唯一，保存人工改过的 `summary` / `detail`。

### 行为

- App 论点详情 → “编辑并固定这条” → 保存。
- Web 后台卡包 → 每个 point 的“编辑/固定”。
- 拉取已有 pack 时，服务端按 `qa_id + point_index` 覆盖 summary/detail，并标 `pinned: true`。
- 重新编译生成同名 `qa_id` 时，Pin 仍然覆盖；旧 pack 也保留原文件。
- Pin 不改 citations、followups、confidence；只改人写的那两句。

### 边界

- qa_id 变了（问题 slug 变化）Pin 不跟随；后续可按 question 归一化匹配。
- 还没有 Pin 历史/回滚；只保留最后版本。
- 还没有逐条 Pin 的权限/多用户隔离（单工作区）。

## 3. 置信度统计校准

### 反馈

- App 卡片“有用 / 没用 / 用了兜底” → `POST /v1/feedback`
- 记录：pack、qa、question、label、当时的 confidence level。

### 校准

- 按 `green / yellow / red` 分档统计：
  - `accuracy = useful / (useful + not_useful)`
  - 每档至少 **5 条**反馈才生效。
- 生效后，`GET /v1/packs/{id}` 把卡片 `confidence.score` 换成实测准确率，标 `calibrated: true`、`calibration_samples`，reason 加 `empirical_calibration`。
- App 显示“实测置信度 75%”；未校准显示“规则置信度 60%”。
- Web 后台 → “校准”：每档样本、有用/没用、准确率、是否生效。

### 为什么不是模型概率

真正的概率校准需要标注集、可靠性曲线、ECE/Brier 等；现在只有现场反馈的**分档经验准确率**。样本 <5 时继续用规则分，避免拿 1 条反馈当 100%。

### 边界

- 反馈有选择偏差（用户只在明显好/坏时点）。
- 没有按问题类型/文档类型分层。
- 还没有置信区间；样本少时数字波动大。

## 4. 验收

- 两份材料同一 metric key 不同值 → Web 出现 1 条高危。
- 点开论点 → 编辑并固定 → 重新拉 pack 仍显示人工内容，标“已固定”。
- 同一置信档点 5 次“有用” → Web 校准显示 100%，pack 的 score=100、calibrated=true；App 显示“实测”。
- 少于 5 条 → 不校准，仍显示规则分。

## 5. 无依据 LLM 开关（v0.5）

- App 设置页开关：**“无依据也允许 LLM 回答”**，默认关闭。
- 关闭：没召回原文 → 不调 LLM，直接红色兜底。
- 打开：没召回原文 → 调 `UNGROUNDED_SYSTEM_PROMPT`，返回通用回答；`ungrounded=true`、`confidence=red/30`、`citations=[]`。
- App 卡片顶部红色提示：“无原文依据 · LLM 通用回答，可能不可靠，重要口径请核对”。
- 这不是“提高置信度”，而是把“拒绝回答”换成“标红回答”；适合临场救急，不适合正式承诺。
